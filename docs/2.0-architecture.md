# DMA 2.0 架构说明

本文描述恶魔小猫工坊 2.0 的执行链。目标是让“模型说完成了”变成可复核的证据，而不是一句自然语言。

## 分层

| 层 | 模块 | 职责 |
| --- | --- | --- |
| 规格层 | `dma/kernel/spec.py` | 把一句话需求固化为 `ModSpec`：功能、文件归属、验收项、约束。 |
| 调度层 | `dma/kernel/workflow.py` | 把规格转成 DAG：骨架 → 功能 → 检查 → 编译 → 运行 → 验收 → 打包。 |
| 门禁层 | `dma/kernel/gate.py` | 解释每个验收 id，生成 `GateCheck`；必需项失败即阻断。 |
| 执行桥 | `dma/kernel_bridge.py` | 绑定 spec / workflow / 快照 / 循环保护，向主循环注入当前任务。 |
| 检查层 | `dma/kernel/checks/` | 176 条规则的静态分析：符号、映射、Mixin、客户端、线程、网络、注册表、数据包、资产、Gradle、生态、版本等。 |
| 工具层 | `dma/kernel/tools/` | 编辑、测试生成、迁移、块模型、纹理、配置界面、资产库、调试模板、矩阵、缓存等。 |
| 主循环 | `dma/agent.py` | 原生 function calling 优先，文本工具协议兜底；所有文件写入归属 feature，构建 / 测试 / 运行时结果回写门禁。 |

## 一次任务的执行顺序

1. `KernelBridge` 读取或生成 `.dma/spec.json`，再读取或重算 `.dma/workflow.json`。
2. 系统提示注入当前应执行的任务；模型按 DAG 顺序调用工具。
3. 每次 `write_file` / `edit_file` 成功后调用 `record_edit`，把文件归属到某个 feature，并把对应任务置为 `running`。
4. 构建前 `before_build` 自动创建快照；`mcdev_build` / `studio_build` 把真实结果写入 `record_build`。
5. `mcdev_gametest` 写入 `record_test`；`mcdev_scenario`（必须包含断言）和 `studio_verify` 写入 `record_runtime`。
6. 结束时 `finalize` 执行静态检查与验收门禁，输出通过 / 阻断项；阻断时不得声称交付完成。

## 验收证据来源

| 验收类型 | 通过条件 |
| --- | --- |
| `build` | Gradle 真实返回成功，或 studio build 报告 `ok=true`。 |
| `test` | GameTest / 测试命令成功并有汇总。 |
| `runtime` | 场景卡片含断言且通过，或开发端验证报告通过；验证任务中缺失时仅警告。 |
| `lint` | 指定级别 / 规则没有 error；未执行静态检查视为未通过。 |
| `file` | 功能声明的文件或目录至少存在一个。 |
| `manual` | 能力矩阵中未自动化项需要人工确认，默认不通过。 |

## 快照与回滚

`SnapshotStore` 默认排除 `build`、`.gradle`、`run`、`.git`、`.dma` 等目录，以及大文件和归档。支持 `diff`、`restore`、`latest_good`、`prune` 和 `bisect`。回滚时不直接删除新文件，而是移动到快照的 trash 目录。

## 循环保护

`LoopGuard` 对同一错误做指纹聚类。重复失败时给出“换方案 / 查文档 / 缩小范围”的建议，而不是无限重试同一个动作。

## 原生工具调用与回退

`ai.request_chat_tools` 发送 OpenAI 兼容的 `tools` / `tool_choice`，解析 `assistant.tool_calls`。通道返回 400/404/422 且错误与 tool/function 相关时抛出 `AIToolsUnsupported`，主循环自动切回文本 ```tool 协议，并在本次会话内记住该通道不支持原生工具。

## 离线与可选依赖

- 核心检查和构建不依赖网络。
- `OfflineCache` 可缓存符号、映射、模板、资产和文档，按 SHA-256 校验并可裁剪。
- 块模型预览、纹理生成需要 Pillow；缺失时返回明确错误，不静默失败。

## 已知边界

- 内置可直接生成的骨架仍是 Minecraft 1.20.1 的 Forge / Fabric / NeoForge；其他版本由助手按官方模板生成并编译验证。
- 游戏内探针只支持 Forge 1.20.1；其他加载器以编译结果、运行日志和 GameTest 为准。
- 能力矩阵中的 `assist` 项有生成器或报告，但仍需人工确认；`manual` 项为 0，不代表所有规则都能脱离人工判断。
